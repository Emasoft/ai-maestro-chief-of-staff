Historical plan (all done):

**Source:** MANAGER work order on THIS repo's **#19** (script↔skill sync audit,
arg-drift half). ~21 drifts in `amp-send`/`aimaestro-agent.sh` calls; several
**fail silently at runtime** (invalid `--type` → exit 1 → caller swallows as
False/[]). Violates the project's fail-fast principle. Acked on #19
(issuecomment-4702962985).

**LOAD-BEARING CONTRACT (verified, do NOT trust the .md doc):** the actual
`amp-send` EXECUTABLE the Python subprocess calls is `~/.local/bin/amp-send`;
its validation (L152) accepts **TEN** `--type` values:
`request|response|notification|task|status|alert|update|handoff|ack|system`.
The MANAGER's 10-type allow-list is CORRECT. The ai-maestro-plugin
`commands/amp-send.md` doc (v2.7.2) is STALE — it says "exactly seven values"
and omits handoff/ack/system. → file a doc-staleness issue on ai-maestro-plugin
(cross-project: file, don't patch). The amp-send positional order
(`<recipient> <subject> <message>`) is already correct everywhere; only the
`--type` VALUES, the phantom subcommand, and the doc examples are wrong.
