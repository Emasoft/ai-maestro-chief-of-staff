## The ratified model (MANAGER Tier-2, COS#11)

The team board is a **simplified projection of the TRDD v2 lifecycle**. Adopt the
**8-column set** (NOT the server's collapsed 5-status set — that would hide the
two distinct governance review gates and the first-class `blocked` lane):

```
backlog · todo · in-progress · ai-review · human-review · merge-release · done · blocked
```

**TRDD `column:` → board lane projection** (a TRDD's frontmatter `column:` drives
its board lane):

| Board lane | TRDD v2 `column:` values that map to it |
|---|---|
| `backlog` | backburner, todo |
| `todo` | dispatch |
| `in-progress` | dev, testing |
| `ai-review` | ai_review |
| `human-review` | human_review |
| `merge-release` | complete, publish, deploy |
| `done` | published, live |
| `blocked` | blocked |

Notes from the ratification:
- ONE `merge-release` lane — the TRDD frontmatter (`release-via`,
  publish-vs-deploy) carries that detail; the lane is not split.
- `ai-review` and `human-review` MUST stay distinct (the R26–R40 dual-review /
  human-gate depends on it; collapsing them hides the human gate).
- `blocked` is a first-class lane (TRDD v2 treats `blocked` as a first-class
  state).
